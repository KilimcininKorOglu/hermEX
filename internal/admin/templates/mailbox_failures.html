Mailbox failures

{{if .Disabled}}

Central logging is not configured, so these failures cannot be listed.

{{else}}

Each row is a delivery the recipient's own database refused for good. The message was deferred rather than rejected, so the sending server keeps retrying and nothing has bounced yet. Every retry fails the same way until the mailbox is repaired.

Report the damage with hermex-admin check-mailbox <address>, which writes nothing and is safe on a running deployment. Repair it with hermex-admin check-mailbox <address> --recover, which rebuilds a damaged database and loses the rows on its damaged pages. Repair refuses while a daemon holds the mailbox open.
