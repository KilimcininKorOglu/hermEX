Command lines

A command line is one line a client sends before anything is stored, so these are in bytes, not megabytes. Without a cap a client that never ends its line grows the daemon's memory, and it reaches these readers before it logs in. Keep the IMAP figure generous: a long UID set or SEARCH is legitimate.

EWS subscriptions

An EWS notification subscription is dropped once it goes unused for this long, so this is in minutes. The timer restarts every time the client uses the subscription, and it is the whole policy for a streaming subscription, whose request carries no timeout of its own. A client away for longer (a sleeping laptop, a roaming network) loses the subscription and cannot tell without subscribing again, so raise it when clients go offline for long stretches. A change applies to new subscriptions; existing ones keep the timeout they were created with.

Request rate limiting is {{if .HTTPRateEnabled}}on{{else}}off{{end}}.

When on, a client address that sends more than the burst within the window is answered with 429 and a Retry-After header, so one client cannot exhaust a daemon for everyone else. It covers every HTTP surface (webmail, EWS, ActiveSync, MAPI/HTTP, DAV, this panel and the gateway) and each daemon counts on its own. Keep the burst generous: Outlook and ActiveSync clients issue large legitimate bursts during an initial sync.

The connection cap is {{if .ConnLimitEnabled}}on{{else}}off{{end}}.

When on, a daemon serves at most the total number of connections at once, and one client address holds at most its own share. A refused connection is told why in the protocol's own greeting (IMAP * BYE, POP3 -ERR, SMTP 421, which makes a sending server retry later rather than bounce the mail) and then closed. It covers IMAP, POP3 and SMTP; each daemon counts on its own. Keep the per-client figure generous: a desktop mail client holds several connections at once, and one address is often a whole office behind a NAT.

A login that fails {{.LoginMaxFails}} times within {{.LoginWindow}} seconds is locked out for {{.LoginLockout}} seconds.

This is what makes online password guessing hopeless. It covers webmail, IMAP, POP3 and this panel; each daemon counts on its own, and every attempt counts twice: once against the account and once against the client address. The address is locked out at four times this threshold, since one address is often a whole office behind a NAT. Tighten it during a credential-stuffing wave, loosen it if legitimate users are being locked out. There is no off switch: raise the threshold instead.

A fetchmail source is dialled by this server on a schedule, so a source pointed at an internal address reaches services that are not exposed to the network at all. Internal, loopback and link-local source addresses are therefore refused unless you allow them here. Turn this on only if you fetch from a server on your own private network. Domain administrators can create fetchmail entries; only a full system administrator can change this.
